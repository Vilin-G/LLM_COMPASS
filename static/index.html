问题先经 router 判断类型：闲聊直接答，学习类问题才去检索笔记。

这个回答是怎么来的

  1. router 判断类型：闲聊直接回答，学习类问题进入检索
  2. retrieve 从 Chroma 里取相关笔记片段
  3. grade 判断片段够不够回答问题
  4. 够 → 生成带来源的回答；不够 → 明确说"笔记中没有相关内容"，不编造
依据：app.py 的 build_graph() 与 README 的架构图

当前阶段（如实说明）

  • POST /ask 只返回一个 answer 字段：路由结果、检索到的片段、评分结论都没进接口。
  • 所以下面的"来源"是从回答文本里解析出的 .md 文件名，不是接口返回的结构化字段。
  • "拒答"和"闲聊"也是按回答文本判断的，不是接口状态；识别不到时会按普通回答展示。

技术栈：FastAPI · LangGraph · LangChain · Chroma · 原生 HTML/CSS/JS

已知限制：知识库只有 notes/ 下两篇笔记，覆盖范围有限；检索片段与评分过程尚未通过接口暴露。
